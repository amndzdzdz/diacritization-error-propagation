## Tasks (from plan §7)

1. **Differentiation text.** Read Kadambi et al. 2024 and Mathad et al. 2021
   (already done per the user), then write the 2–3 paragraphs distinguishing
   window-shifting (alignment) corruption from label-shifting (diacritic)
   corruption. Draft in `docs/differentiation-kadambi-mathad.md`; this text is
   destined for the introduction and related work.
2. **Pre-committed effect-size position.** One paragraph, signed off by both
   students, committing in advance to report a small effect honestly rather
   than reframe under deadline pressure. Draft in
   `docs/effect-size-position.md`.
3. **Dataset access. 🟡 Partially done.** Access to `QuranMB.v2` and
   `Iqra_Extra_IS26` is confirmed (per the user, 20 Sep 2026). Still open:
   confirm licence terms explicitly for both, and establish whether
   `QuranMB.v2` test labels are public or leaderboard-held — access alone
   doesn't answer that.
4. **CATT token-probability check. ✅ Done — see
   [insights/week-01.md](../../insights/week-01.md).** CATT does not expose
   confidence through its public interface (`do_tashkeel`/
   `do_tashkeel_batch`), but the underlying ONNX decoder session inside the
   `catt-tashkeel` package computes raw per-position logits before argmax;
   calling the package's non-public methods directly and applying softmax
   recovers usable per-character confidence (verified against the EO
   checkpoint, confidence range 0.48–1.0 on a sample sentence, reconstructed
   text matched `do_tashkeel()`'s output exactly). Decision: proceed with
   CATT for RQ4, vendor the extraction logic into
   `src/arabic_mdd/diacritizers/` with proper tests when the Week 4–6
   diacritizer pipeline is built — the private-method dependency is
   acceptable for this feasibility check but not for the shipped pipeline.
   Still open: confirm the same technique on the ED checkpoint before
   deciding which CATT variant RQ4 uses.
5. **Cluster confirmation. 🟡 Partially done.** Queue time limit confirmed
   as unrestricted (per the user, 20 Sep 2026: "Timelimit: Infinite"). Still
   open: an actual wall-clock estimate for one XLS-R-300m fine-tuning run —
   no time limit doesn't tell us how long a run takes or how many are
   affordable in the 21-week budget.
6. **QuranMB v1/v2 overlap. ✅ Resolved — see
   [novelty-check.md's third secondary result](../novelty-check.md).**
   v1 and v2 are different benchmarks, not the same test set (v1: 98
   verses/18 speakers, mHuBERT baseline F1 = 29.88%, from "Towards a Unified
   Benchmark," Interspeech 2025, arXiv 2506.07722; v2: 1,643 utterances,
   introduced later the same year by the Iqra'Eval 2025 shared task,
   ACL Anthology 2025.arabicnlp-sharedtasks.61, organizer baseline F1 =
   44.14%). The "digit-for-digit" match is between IQRA 2026's leaderboard
   baseline and the **2025** Iqra'Eval shared task's own baseline on the
   same v2 test set — IQRA 2026 is the second edition of that shared task
   and carried the first edition's baseline forward unchanged rather than
   re-measuring it. Consequence: this project's week 1–3 gate ("reproduce
   the mHuBERT baseline at F1 ≈ 0.4414 ± 0.02") should cite
   2025.arabicnlp-sharedtasks.61 as the baseline's source, not arXiv
   2603.29087 (IQRA 2026) — `docs/mdd-paper-project-plan-v2.md` §6/§7
   currently doesn't distinguish these and should be corrected. Does not
   change the experimental design, exactly as the plan anticipated.
